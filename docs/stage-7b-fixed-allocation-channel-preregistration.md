# Stage 7B0 Preregistration: Scripted Acquisition-Allocation Channel Verification

**Protocol status:** frozen before any Stage 7 mixed-treatment population response, mutation run, invasion assay, or evolutionary run. This document registers a scripted state-machine verification against the isolated Stage 7 reference mechanics. Stage 7 currently has no executable VM genome, program counter, or instruction-stream control flow; this protocol therefore makes no genome-level claim.

**Evidence-era disclosure:** before this protocol freeze, deterministic design calibration observed the Block A arithmetic, direct two-generation object construction at candidate treatment values, and the Block E reversal quantities. Those values are retained treatment regressions and provide no prospective confirmation. Before freeze, the registered normal-scheduler Block B fixture, low-budget recovery Block C fixture, and label-permuted shared-buffer Block D fixtures had not been run. No population response, fitness endpoint, or selection result has been observed.

**Authorisation:** this document authorises no execution by itself. Before first registered execution, the implementation, runner, tests, output schema, and analysis must be frozen together under §10. No Stage 7B1 population-fitness or evolutionary work is authorised.

## 1. Registered question

For the exact programme specification, treatment points, opening states, and trace blocks registered here, does intervening on the lifetime-fixed acquisition-allocation numerator `A`:

1. split the same positive extraction income exactly between somatic reserve `S` and reproductive reserve `R`;
2. preserve direct-debit isolation, with reproduction-specific variable work, gestation upkeep, and offspring provisioning absent from parent `S`;
3. produce the registered differences in reproductive funding and child endowment while the procedural path, operation count, packet geometry, and configured source topology remain fixed;
4. recover reproductive competence after a registered `R`-insufficient attempt without debt or `S→R` subsidy; and
5. preserve exact reserve, packet-provenance, shared-memory, and census closure at the named checkpoints?

This is a fixed-state mechanism verification. It is not a test of population fitness, intrinsic fecundity, selection, invasion growth, reproductive value, allocation plasticity, an optimum, or an ESS.

### 3.2 Treatment-choice rule and results

The registered intervention uses the widest non-boundary pair in the searched interior set: `A=102` and `A=204`. This choice was made to produce a large account-allocation contrast without the intentionally degenerate `A=0` or `A=D` endpoints. It is not claimed to be optimal or uniquely informative.

For that fixed pair, the candidate `T` values were checked in the stated ascending order. Acceptance required both arms' child objects to complete the same perfect-capture forage–reproduction cycle and construct a grandchild without debt, hidden reserve threshold, or floating-point residue.

- `T=51`: LOW failed before completing the child cycle;
- `T=102`: LOW failed before completing the child cycle;
- `T=128`: both LOW and HIGH completed;
- `T=153` and `T=204`: both completed but were checked only as later candidate values.

`T=128` is therefore the first passing value in the disclosed candidate set, not the globally minimal integer numerator. The exact global minimum was not searched and is not claimed. `T=128` is a fixed Stage 7 treatment constant, not historical single-reserve `τ` and not a provisioning optimum.

The live pre-income somatic runway under this procedural path is `2859/160`. Candidate completion was assessed by actual exact execution, not by installing that value as a birth gate.

### 3.3 Reversal calibration correction

## 5. Named checkpoint equations

### 5.1 Isolated scripted blocks A, C, and E

At checkpoints `INITIAL`, `POST_FORAGE`, `POST_ALLOC`, `POST_COPY`, `POST_DIVIDE`, `POST_REVERSAL`, and `FINAL`, as applicable:

`parent_S + parent_R + committed_child_S + destroyed = opening_S + opening_R + gross_income - reversed_income - C_S - C_R`

`packet_budget_remaining + packet_drawn_S + packet_drawn_R = packet_initial_budget`

`free_pool + somatic_active + gestation + corpse_reserved = initial_memory_pool`

`committed_child_S` is an internal transfer held outside the parent object in the isolated harness; it is not an energy sink. `destroyed` contains only explicit dissipation represented by the live mechanics.

### 5.2 Population blocks B and D

At `INITIAL`, `POST_PACKET_ARRIVAL`, after each scheduled member transition, after each admission/rejection, and `TICK_COMPLETE`:

`live_S_R + terminal_disposed + organism_destroyed = founder_inputs + gross_income - reversed_income - C_S_R`

where `live_S_R=Σ_live(S+R)` and `C_S_R=Σ(C_S+C_R)`. Parent provisioning and child `S_birth` are one internal transfer and do not appear as a sink.

For every captured packet still represented by a live packet ledger:

`budget_remaining + drawn_S + drawn_R = initial_budget`

Every unread buffered packet must retain `e_budget=e_initial`. The registered fixtures prevent buffer overflow and packet eviction. Any eviction is an `INVALID IMPLEMENTATION`, because the current buffer would otherwise discard unlogged energy. General packet destruction and provenance-retirement accounting are deferred prerequisites for Stage 7B1.

Memory closure is:

`free_pool + somatic_active + gestation + corpse_reserved = initial_memory_pool`

Census closure is:

`founders + admitted_births - hazard_removals = live_census`

Rejected births change neither census nor committed provisioning. At each registered checkpoint there must be no leaked vacancy, child-memory, or gestation reservation.

## 7. Primary gates and decision

Stage 7B0 is **PASS** only if every block and every gate passes under one frozen source manifest.

1. **Realised treatment:** all runtime `A,T,D` values and descendants equal §4; mutation is disabled and no mutation RNG is consumed.
2. **Programme identity:** both arms report the same programme-specification hash. Transition sequence and operation count match within each paired block.
3. **Allocation identity:** every positive draw satisfies `Y_S=(1-A/D)Y`, `Y_R=(A/D)Y`, and `Y_S+Y_R=Y` exactly.
4. **Direct-debit isolation:** reproduction-specific variable work, live gestation upkeep, and `P` debit `R`; common dispatch and somatic upkeep debit `S`.
5. **Reversal provenance:** Block E uses stored packet provenance, not current or reconstructed allocation ratios, and fails atomically after spending.
6. **Recovery:** Block C fails and recovers at the exact registered transitions with no extra opportunity.
7. **Lifecycle:** Block B completes the exact two-tick parent→child→grandchild event sequence in both arms with no censoring.
8. **Topology:** Block D uses one consumptive buffer; generated/captured counts and label permutation match exactly. Private per-organism packets are an automatic FAIL.
9. **Closure:** every named checkpoint satisfies §5 exactly.
10. **No hidden gate:** no birth-reserve threshold, clamp, offspring deletion, incumbent displacement, floating-point viability rule, or unregistered opportunity occurs.

Decision classes:

- **PASS:** all ten gates pass in all registered blocks.
- **FAIL:** the realised registered implementation violates any causal, transition, recovery, lifecycle, topology, or closure gate.
- **INVALID IMPLEMENTATION:** source/manifest mismatch, wrong fixture, missing raw output, unregistered packet eviction, or failure to realise the registered protocol. Invalid execution provides no mechanism result.

No gate may be added, removed, weakened, reinterpreted, or replaced after output inspection.
